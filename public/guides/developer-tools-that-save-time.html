Why Browser Tools为什么用浏览器工具

There is an argument for command-line or IDE solutions to all of these, and for work you do constantly, that is right. But there is a real case for browser tools too:这些事当然都可以用命令行或 IDE 解决，如果你天天做，那确实该那么做。但浏览器工具也有它实实在在的理由：

  • Nothing to install — works on a locked-down work machine, a borrowed laptop or a phone不用安装 —— 在受限的办公电脑、借来的笔记本甚至手机上都能用
  • Visual feedback — regex match highlighting and JSON error positions communicate better than terminal output有视觉反馈 —— 正则匹配高亮和 JSON 报错位置，比终端输出直观得多
  • Shareable — you can send a link to a colleague showing exactly what you mean可分享 —— 发一条链接给同事，就能准确表达你的意思
  • No context switching — no need to remember whether you installed jq on this machine不用切环境 —— 不必记得到底有没有在这台机器上装过 jq

Json ValidationJSON 校验

A parser telling you "unexpected token" is nearly useless. JSONLint reports the line and position, and describes what it expected — which turns a hunt into a fix.解析器只告诉你「unexpected token」，基本等于没说。JSONLint 会报出错误在第几行第几个字符，还会说明它期望的是什么 —— 把一场排查变成一个改动。

It reliably catches the mistakes that actually occur: trailing commas after the last array element, single quotes instead of double, unescaped characters inside strings, comments (which JSON forbids) and mismatched brackets. Once valid, it pretty-prints or minifies in the same place.它能稳稳抓到实际会犯的那些错：数组最后一个元素后面多了逗号、用单引号代替双引号、字符串里没转义的字符、注释（JSON 不允许），以及括号不匹配。校验通过后，还能在同一个地方格式化或压缩。

Regex Testing正则测试

Regex fails silently: it matches the wrong thing, or nothing, and the reason is not obvious. Regex101 highlights matches live and — the genuinely valuable part — explains each token in plain language, so you learn why the pattern behaves as it does.正则是静默失败的：它匹配错了东西，或者什么都没匹配上，而原因并不明显。Regex101 会实时高亮匹配结果 —— 真正有价值的是 —— 它还会用大白话解释每一个符号，于是你能搞懂这个正则为什么会这样表现。

note要避免的错误 用错的引擎做测试。正则语法在 PCRE、JavaScript、Python 和 Go 之间并不一样，一个模式在这边能跑、在那边可能就失败。调试前一定要选对你代码实际使用的那一档。

The debugger is also worth opening when a pattern is slow, because it makes catastrophic backtracking visible.当某个正则跑得很慢时，也值得打开它的调试器，因为它能让灾难性回溯暴露出来。

Timestamps And Encoding时间戳与编码

Timestamps时间戳

EpochConverter translates between Unix timestamps and readable dates in both directions, and its explicit seconds/milliseconds toggle resolves the most common timestamp bug. The rule: a 10-digit value is seconds, 13 digits is milliseconds. Getting it wrong produces 1970 dates or dates decades in the future.EpochConverter 在 Unix 时间戳和可读日期之间双向转换，它那个明确的秒/毫秒开关能解决最常见的时间戳 bug。规律是：10 位通常是秒，13 位是毫秒。搞反了就会得到 1970 年的日期，或者几十年后的日期。

Base64Base64

Use it for transport, never for secrecy — it decodes instantly. It is genuinely useful for data URIs, but remember the roughly 33% size overhead, so keep embedded images to small icons.用它做传输编码，绝不要用来保密 —— 它一秒钟就能被解出来。它对 data URI 确实有用，但记住大约 33% 的体积开销，所以内嵌图片只适合小图标。

UUIDsUUID

Generate version 4 unless you have a specific reason not to. Version 1 embeds a timestamp and MAC address, which can leak more than you intend in a public API. Random UUIDs fragment database indexes more than sequential keys, so weigh that for very large tables.除非有特殊理由，否则一律生成 version 4。v1 会嵌入时间戳和 MAC 地址，在公开接口里可能泄露超出你预期的信息。随机 UUID 比顺序键更容易让数据库索引碎片化，超大型表要权衡这一点。

Building A Workflow串成工作流

The tools pay off most when used in a consistent order rather than reached for at random:这些工具按固定顺序用，比随手抓一个用收益大得多：

  1. Inspect before debugging. Paste an API response into a formatter first — most "bugs" are just unreadable structure.先看清结构，再调试。 先把接口响应粘进格式化工具 —— 大多数「bug」其实只是结构看不清。
  2. Validate assumptions early. Validate JSON and test regex against real sample data, not invented data.尽早验证假设。 用真实的样本数据去校验 JSON、测试正则，而不是用自己编的数据。
  3. Watch your units. Check timestamps for seconds versus milliseconds before assuming a data problem.盯住单位。 先确认时间戳是秒还是毫秒，再下结论说数据有问题。
  4. Confirm the environment. Match the regex engine to your runtime.确认运行环境。 测试时选择和你所用语言一致的正则引擎。
  5. Bookmark the set. Keep them in one browser folder so the tool is never the reason you stall.整组加书签。 放在同一个浏览器文件夹里，别让「找工具」成为你卡住的理由。
tip安全习惯 这些工具永远不该接收生产环境凭证、私钥或真实客户数据。调试时请造一份一次性样本数据来用。

Frequently Asked Questions常见问题

Are online developer tools safe to use?在线开发者工具安全吗？

For non-sensitive data, yes. Never paste production credentials, private keys or real customer data into any online tool — generate sample data instead.非敏感数据没问题。但永远不要把生产环境凭证、私钥或真实客户数据粘进任何在线工具 —— 应该造一份样本数据。

Which JSON validator is best?哪个 JSON 校验工具最好？

JSONLint is the standard choice because it reports the exact line and position of the error rather than a generic parse failure.JSONLint 是标准选择，因为它会报出错误所在的具体行和位置，而不是笼统地说解析失败。

Why does my regex work online but not in my code?为什么正则在线上能匹配，到我代码里就不行？

Almost always an engine mismatch. Select the flavour matching your language in Regex101 before testing.几乎都是引擎不一致。测试前先在 Regex101 里选择和你所用语言匹配的那一档。

Seconds or milliseconds — how can I tell?秒还是毫秒 —— 怎么判断？

A 10-digit timestamp is usually seconds; 13 digits usually means milliseconds. This single check resolves most timestamp confusion.10 位时间戳通常是秒；13 位通常意味着毫秒。这一条检查就能解决大部分时间戳困惑。

Should I use v1 or v4 UUIDs?该用 v1 还是 v4 的 UUID？

v4 (random) for nearly everything. v1 embeds a timestamp and MAC address, which can leak information.几乎所有场景都用 v4（随机）。v1 会嵌入时间戳和 MAC 地址，可能泄露信息。

Do I need to install anything to use these?用这些需要安装什么吗？

No. All of them run in a browser tab, which is why they work on locked-down or borrowed machines.不需要。它们全部在浏览器标签页里运行，这也是它们在受限电脑或借来的机器上也能用的原因。
